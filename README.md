# Paywall Demo

[![style: very good analysis][very_good_analysis_badge]][very_good_analysis_link]

Тестовое задание: приложение с флоу **Онбординг → Paywall → Главный экран** и
сохранением подписки между запусками.

```
первый запуск ──→ Онбординг (2 экрана) ──→ Paywall (Месяц / Год) ──→ Главный экран
повторный запуск с активной подпиской ─────────────────────────────→ Главный экран
```

Бэкенда и реального биллинга нет: покупка эмулируется в репозитории (задержка
~1.2 с + локальная запись), статус подписки лежит в `SharedPreferences`.

Развёрнутая версия этого документа — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Запуск

Flutter через FVM (`.fvmrc`, 3.44.1). Флейвор обязателен.

```sh
make run          # development
flutter analyze   # No issues found!
flutter test      # 33 теста, зелёные
```

В development-сборке в углу каждого экрана есть кнопка «жучок» — панель отладки:
сброс онбординга, выдача/сброс/протухание подписки, чтобы проходить флоу заново
без переустановки.

## 1. Архитектура

Слоистая feature-архитектура: `core/` — инфраструктура, `feature/<name>` — фичи.
Фича может импортировать `core`, обратно — никогда. Основа взята из внутреннего
шаблона, продуктовые фичи `onboarding` и `subscription` написаны под задание.

**Стартовым экраном управляют гарды Auto Route на ветке `/`** — экраны не решают,
куда идти дальше: они меняют состояние и просят роутер перепроверить гарды.

```
навигация в `/`
   ├─ OnboardingGuard:   онбординг не пройден ──→ /onboarding
   ├─ SubscriptionGuard: подписки нет ──────────→ /paywall
   └─ оба пропустили ───────────────────────────→ Home
```

Так решение о доступе живёт в одном месте и работает не только на холодном
старте: истечение подписки и сброс состояния обрабатываются тем же кодом. Цена
решения — два правила: состояния, которые читают гарды (`OnboardingCubit`,
`SubscriptionBloc`), поднимаются из prefs **синхронно в конструкторе**, а
`reevaluateGuards()` вызывается из `BlocListener` на новое состояние, а не сразу
после `add(event)` — иначе гард проверит старые данные.

Остальное коротко:

- **Состояние** — BLoC; статус и выбранный тариф лежат на всех ветках состояния,
  поэтому UI не мигает. Покупка — `droppable`: двойной тап не купит дважды.
- **DI** — ручные scope на `InheritedWidget`, без сервис-локатора. Онбординг и
  подписка подняты выше роутера, чтобы гарды успели их прочитать.
- **Данные** — `ISubscriptionRepository` имеет форму настоящего
  (`purchase` / `restore` / типизированные ошибки): эмуляцию можно заменить на
  `in_app_purchase` или RevenueCat, не трогая блок и UI. Хранение — типизированные
  DAO поверх `SharedPreferences`.
- **Активность подписки не хранится флагом**: в prefs лежит `expiresAt`, а
  `isActive` — это `expiresAt.isAfter(now)`. Флаг рано или поздно разошёлся бы с
  реальностью, дата — нет.
- **На пейволе нет ни одного вписанного руками числа**: цена за месяц, процент
  экономии и триал считаются из `SubscriptionPlan`. Поменяли цену в enum — экран
  пересчитался целиком.
- Тексты — только через `context.l10n` (ARB, `ru`), логи — только через
  `mainTalker`, сырые исключения пользователю не показываются.

## 2. Структура проекта

```
lib/src/
  core/                  # api, bloc-базы, database, router, theme, utils, widget
  feature/
    onboarding/          # ← под задание: cubit, dao, /onboarding + OnboardingGuard
    subscription/        # ← под задание: paywall, модели, dao, bloc,
                         #   /paywall + SubscriptionGuard
    app/                 # бутстрап, корневые роуты, оболочка, панель отладки
    home/ settings/      # главный экран, тема и конфиг
    auth/ user/          # авторизация необязательна: пользователь — гость
    notification/        # push: код есть, не инициализируется (вне объёма)
config/                  # development.json / production.json
packages/client_api/     # Retrofit-клиент и DTO (не на пути флоу)
test/                    # 33 теста
```

Каждая фича устроена одинаково: `model/` → `database/` → `data/` → `bloc|cubit/`
→ `scope/` → `router/` → `view/` + `widget/`.

Drift, Retrofit, Firebase и авторизация достались от шаблона и во флоу
**не участвуют** — пейвол не зависит от сети и `API_BASE_URL`.

Тесты покрывают расчёт цен и экономии, запись покупки в prefs и её переживание
перезапуска, самостоятельное протухание подписки по дате, поведение блока
(включая отброшенный повторный тап) и обе цепочки гардов.

## 3. Что улучшил бы при большем времени

- **Реальный биллинг** (`in_app_purchase` / RevenueCat) с серверной валидацией
  чеков — интерфейс репозитория уже под это заточен. Сейчас `restore()` читает
  локальные prefs, это эмуляция, а не восстановление из стора.
- **Реакция на истечение подписки в рантайме** через
  `reevaluateListenable` — роутер сам перепроверял бы гарды на эмит блока.
- **Главный экран**: сейчас заглушка из шаблона, довёл бы до плашки активной
  подписки и списка контента.
- **Конфиг пейвола с сервера и A/B тарифов** — сейчас цены живут в enum.
- **Аналитика воронки** (показ пейвола → выбор тарифа → покупка): без неё пейвол
  нечем улучшать осмысленно.
- **Тесты**: интеграционный прогон всего флоу с перезапуском и golden на пейвол.
- **Тёмная тема и адаптивность** пейвола под маленькие экраны.
- **Убрал бы дремлющую инфраструктуру** шаблона (Firebase, Drift, Retrofit,
  авторизацию) либо довёл её до дела — на ревью она раздувает объём кода.
